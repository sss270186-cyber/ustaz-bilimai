# Backup және staging үшін қауіпсіз авторизация

## Рұқсат шекарасы

Пайдаланушы backup жасауға, қалпына келуін тексеруге, бөлек hosted Supabase staging жобасына, оның миграциялары мен сынақ аккаунттарына және Vercel Preview-ге рұқсат берді. **Production дерекқорын өзгерту, Production аккаунттарын жасау/жою/құпиясөзін ауыстыру, PR-ды main-ге біріктіру немесе Production deployment үшін бөлек нақты растау керек.**

| Қызмет | Қажетті қолжетімділік | Қолданылуы |
| --- | --- | --- |
| Supabase Production | Жоба баптаулары мен backup мәртебесін оқу; backup жасау/жүктеу немесе database-owner dump connection | Деректерді өзгертпей, қалпына келетін DB/Auth көшірмесін алу |
| Supabase organization | Бөлек staging жобасын құру немесе дайын бөлек жобаға кіру | Production-нан оқшауланған орта |
| Supabase staging | Restore, DDL/migration, RLS/functions және synthetic Auth аккаунттарын басқару | Backup қалпына келуі мен интеграциялық тесттер |
| Vercel Ustaz BilimAI | Жоба/Preview күйін оқу, Preview айнымалыларын өзгерту, Preview build/deployment және логтарын оқу | Preview-ді тек staging базасына қосу |
| GitHub репозиторийі | Жеке тармақ, commit, PR және CI | Бар PR №1 арқылы өзгерістерді қарау; merge жасалмайды |

Production backup қызметінің нақты рұқсаттары Supabase жоспарына және provider қолдайтын рөлдерге байланысты. Қолданбалық `service_role` кілті database-owner connection немесе Supabase Management API токені емес; оған сүйеніп толық backup жасалды деп есептеуге болмайды.

## Бірінші жол: ресми интеграцияның қосылу терезесі

1. Осы ChatGPT workspace әкімшісі Supabase және Vercel интеграцияларын пайдалануға рұқсат етеді. Қазіргі тексеруде екеуі де `DISABLED_BY_ADMIN / NOT_AVAILABLE`: пайдаланушының чаттағы «рұқсат беремін» жауабы бұл әкімшілік саясатты өзгертпейді.
2. Рұқсат берілген соң пайдаланушы ChatGPT-нің интеграцияны қосу интерфейсінен ресми Supabase/Vercel қосылу терезесін ашады. Провайдер ұсынатын авторизацияны сол терезеде аяқтайды. Егер OAuth ұсынылса, провайдердің consent беті пайдаланылады.
3. Провайдер мүмкіндік берген деңгейде тек қажетті organization/project таңдалады. Көрсетілген нақты scopes тексеріледі; шектеулі scopes бар деп алдын ала есептеуге болмайды.
4. Қосылу расталған соң ассистент қолжетімді құралдарды қайта тексереді, алдымен read-only күйін алады. Интеграцияда backup экспорт/restore мүмкіндігі болмаса, төмендегі database connection жолы қажет болуы мүмкін.

Ассистент әкімші шектеуін өз бетімен алып тастай алмайды; қосылмаған интеграцияны қосылды деп көрсетпейді.

## Балама: бұлттық ортаның қорғалған құпиялары

Бұлттық ортаның secret/configuration интерфейсін пайдаланыңыз. Кілттерді чатқа, PR-ға, GitHub Actions логына немесе репозиторийге енгізбеңіз.

- `SUPABASE_ACCESS_TOKEN` — қажет organization/project-ке қолжетімді account-тың Supabase Management API токені. Жеке токеннің нақты scope-ы провайдердегі account рұқсаттарына тәуелді; оны автоматты түрде project-only деп санауға болмайды.
- `SUPABASE_DB_URL` — DB/Auth толық dump жасауға жеткілікті database connection, парольді қоса толық URI болса да тек secret өрісінде сақталады. Пәрмен жолына не логқа шығарылмайды.
- `VERCEL_TOKEN` — мүмкіндігінше тиісті командамен шектелген, қысқа жарамдылық мерзімі бар токен. Vercel жобасының ID-лері secret емес конфигурация ретінде берілуі мүмкін.

Желілік конфигурацияда `api.supabase.com`, `api.vercel.com`, нақты staging/Preview домендері және PostgreSQL қосылатын нақты host/port рұқсат етілуі керек. HTTP API үшін токен тиісті provider доменімен байланыстырылсын. DB байланысына TCP рұқсаты бөлек қажет; HTTP allowlist оны алмастырмайды. Proxy мен TLS тексеруі сақталады.

Құпиялар қосылғаннан кейін орта олардың мәнін көрсетпей, дайындық күйін растауы керек. Қазір бұл management/DB/Vercel credentials жоқ. Бар Production app keys жаңа hosted staging жасауға жеткіліксіз.

## Авторизациядан кейінгі орындалу реті

1. Production-ның деректер мен Auth схемасын қамтитын толық backup-ын қорғалған орында жасау. Қолданылған әдіс, уақыт, checksum және қалпына келу шектеулерін тіркеу. Backup ішінде пайдаланушы деректері/құпиясөз хэштері болуы мүмкін; ол ашық репозиторийге қосылмайды.
2. Backup-ты бөлек staging-ге restore етіп, кестелерді, RLS/functions, аккаунт сәйкестігін және provider қолдайтын Auth қалпына келуін тексеру. Backup-ты staging-де тексермей «қалпына келеді» деп белгілемеу.
3. Жаңа миграциялар мен seed-ті staging-ге қолдану. Қазір19 тақырыптың әрқайсысына2 B + 10 C,барлығы228 тапсырма әзірленген. Бұл hosted Production-да ашылды дегенді білдірмейді.
4. Vercel Preview-дің environment scope-ын тек Preview/staging ретінде орнатып, Production variable-дарын өзгертпей қайта құрастыру.
5. Теория/формулалар/12 шешімді, нақты Auth, оқушы тіркеу, RLS, тапсырма орындау, жауап тексеру, сақтау, қайта кіру және мұғалім нәтижелерін тексеру. Жеке staging қорғаныс скрипті: `npm run test:staging`.
6. Пайдаланушыға staging URL, өткен/өтпеген тексерулер, backup restore нәтижесі және Production жоспарын беру. **Осыдан кейін бөлек Production растауын күту.**
