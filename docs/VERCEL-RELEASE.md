# Ustaz BilimAI — бұрынғы Vercel мекенжайында іске қосу

Мақсат: **https://ustaz-bilimai.vercel.app/**. Өзгерістер **PR №1** ішінде ғана: https://github.com/sss270186-cyber/ustaz-bilimai/pull/1.

**Бұл құжат — дайындалған жариялау тәртібі. Нақты дерекқорға SQL орындалмады, PR біріктірілмеді, Production жарияланбады.** Жариялау мен дерекқорға өзгеріс енгізу үшін иесінің бөлек рұқсаты қажет. Қосымша Preview, демо, PostgreSQL орнату немесе ChatGPT Sites қажет емес.

## Қандай нұсқа дайындалды

| Қызмет | Жаңа Vercel нұсқасы |
|---|---|
| Сайт | `index.html`, `assets/`, `student.js`; телефон/компьютер интерфейсі |
| Оқу | 19 толық теориялық сабақ; әр тақырыпта 2 B және 10 C — 228 тапсырма |
| Кіру | Бұрынғы Supabase Authentication; мұғалім email/құпиясөз, оқушы мұғалім берген логин/құпиясөз |
| Ортақ нәтижелер | Сол Supabase жобасының `public.unt_attempts` кестесі; сервер есептейді |
| Мұғалім | Өз оқушылары, тіркеу, топқа қосу, қателер/тақырыптар, CSV есеп, тапсырма өңдеу, жасыру/ашу |
| Құпиясөз | Өз құпиясөзін тексеріп өзгерту; мұғалім тек өз тобындағы оқушыға жаңа құпиясөз береді |
| ҚМЖ | Жаңа сайттан алынды; бастапқы Python файлы Git тарихымен бірге сақталған, Vercel-ге берілмейді |

Серверлік алты қызмет: `/api/config`, `/api/learning`, `/api/students`, `/api/tasks`, `/api/password`, `/api/results`. Олар Vercel Node функциялары ретінде жұмыс істеуге дайындалды. Қосымша тұрақты сервер немесе ақылы дерекқор қажет емес; хостингтің тариф шектері қолданылады.

ChatGPT Sites-тің жеке worker, D1, арнайы кіру және секрет байланыстары алынды. `platform/` пен `preview/` белсенді кодтан шығарылды, бұрынғы нұсқа Git тарихында сақталған. Олардың орнына бұрыннан бар Supabase Auth, PostgreSQL/RLS және Vercel API қолданылады. Sites жариялау рұқсаты енді қажет емес. Бұрынғы Sites сынақ базасының мәліметтері негізгі Supabase-ке көшірілмейді.

## Бұрынғы аккаунттар қалай сақталады

- **Supabase жобасы ауыстырылмайды.** Бастапқы жобаның адресі `https://kbnwfuvfnspanoomusmu.supabase.co` екенін панельде тексеріңіз.
- `auth.users` пен `public.profiles` жолдары жойылмайды және қайта құрылмайды. Логин, email, құпиясөз және пайдаланушының UUID нөмірі сақталады.
- Оқушының бұрынғы кіру сәйкестігі сақталған: `логин@students.ustaz-bilimai.example.com`. Бұрынғы аккаунттар осы сәйкестіктен өзгеше болса, іске қосу алдында нақты аккаунтпен тексеру қажет; жаппай қайта тіркеуге болмайды.
- Оқу үшін жаңа `unt_` кестелері қосылады. Бір мұғалім болса, бар оқушылар соның тобына байланысады. Бірнеше мұғалім болса, иелік болжанбайды: мұғалім өзінің байланыстырылмаған оқушыларын логинмен қосады; басқа мұғалімнің оқушысын тартып ала алмайды.
- 006 миграция профильдерге клиенттен жазуды шектейді және оқушыға тек өз профилін оқытады. Профиль жазбалары мен бұрынғы саясаттар сақталады. Ескі бағдарламаның браузерден профильді өзгерту мүмкіндігіне бұл саясат әсер етуі мүмкін; жаңа сайт мұны сервер арқылы орындайды. Рөлдер тек бұрынғы сенімді мұғалім профилінен бекітіледі.
- Басқа бұрынғы нәтижелер кестелері жойылмайды; олардың мазмұны жаңа `unt_attempts` кестесіне автоматты көшірілмейді.
- Құпиясөзді жаңарту нәтижелерді өшірмейді. Ескі қолданба сеанстары жаңа оқу нәтижелеріне қол жеткізе алмайды; қайта кіру қажет.

## Соңғы әрекеттер: тек жариялауға бөлек рұқсат берілгеннен кейін

### 1. Supabase: бастапқы жобада оқу жүйесін қосу

Браузерде **Supabase → бұрынғы жоба → SQL Editor → New query** ашыңыз. Басқа бағдарлама орнатылмайды.

Алдымен [ops/vercel-preflight.sql](../ops/vercel-preflight.sql) файлын толық көшіріп, **Run** басыңыз. Бұл тек оқиды, өзгертпейді. `profiles`, `auth_users`, `auth_sessions` болуы, профильде `id`, `username`, `full_name`, `role`, `class_name`, `created_at` болуы және бұрынғы мұғалімнің `teacher` рөлі тексеріледі. Аккаунт санын салыстыру үшін өзіңізге жазып алыңыз; құпиясөз/кілт жіберудің қажеті жоқ.

**Егер `unt_topics` және `unt_tasks` екеуі де `NULL`, оқу функциялары жоқ болса:** [supabase/releases/20261026_initial_release.sql](../supabase/releases/20261026_initial_release.sql) файлын GitHub-та ашып, **Raw** арқылы толық мәтінді көшіріңіз. Жаңа SQL сұрауына қойып, тек бөлек рұқсаттан кейін **Run** басыңыз. Бұл алты миграцияны ретімен бір транзакцияда орындайды: қате болса, осы орнатудың бәрі кері қайтарылады. Бұрынғы аккаунттар өзгермейді. Файлда жауаптар бар: ол тек SQL Editor-ға арналған, сайтқа жүктелмейді.

**Егер кез келген `unt_` нысаны бұрыннан бар болса:** жалпы орнату файлын орындамаңыз. Тек жетіспейтін миграцияларды анықтап қолданыңыз; бар тапсырмаларды, мұғалім өзгерістерін немесе нәтижелерді қайта seed жасауға болмайды. Скрипт қайталап орнатудан өзі де бас тартады. Нақты Production сұлбасын осы ортадан растау мүмкін болмады; осы тексеру орнату жолын анықтайды.

Соңында [ops/vercel-acceptance.sql](../ops/vercel-acceptance.sql) орындаңыз. Ол тек оқиды: 19 жол, әрқайсысында `b=2`, `c=10`, барлығы `tasks=228`, `keys=228` болуы керек. Үш қауіпсіздік мәні де `false` болуы керек. Бұрынғы аккаунт санын қайта салыстырыңыз.

Supabase **Authentication** баптауында ашық өздігінен тіркелу мен аноним кіру өшірулі екенін тексеріңіз. Оқушыны тек мұғалім сервер арқылы тіркейді. Барлық аккаунтты өшіруге немесе құпиясөздерін ауыстыруға болмайды. **Data API → Exposed schemas** тізіміне `unt_private` қоспаңыз. Қалыпты `public` жеткілікті.

### 2. Vercel: бар жобаның үш баптауын тексеру

**Vercel → `ustaz-bilimai` → Settings → Environment Variables**. **Production** ортасында мына атаулар болуы керек:

| Атауы | Қай мән |
|---|---|
| `SUPABASE_URL` | Сол бұрынғы Supabase жобасының URL адресі |
| `SUPABASE_PUBLISHABLE_KEY` | Сол жобаның publishable немесе бұрынғы `anon` кілті |
| `SUPABASE_SERVICE_ROLE_KEY` | Сол жобаның серверлік `service_role` әкімшілік кілті |

Бар мәндер дұрыс болса, ауыстырмаңыз. Құпия мәндерді чатқа, GitHub файлына немесе суретке жібермеңіз. Әкімшілік кілтке `NEXT_PUBLIC_` / `VITE_` префиксін қоспаңыз. Қалыпты publishable/anon кілті браузерде қолданылады; қорғаныс сервер мен RLS арқылы жасалады. Service Role Key тек серверде қалады.

**Settings → Git** ішінде осы репозиторий және негізгі Production тармағы `main` екенін; **Build and Deployment** ішінде түбір каталогы репозиторий түбірі, Node.js **24.x** екенін тексеріңіз. `vercel.json` алты API мен рұқсат етілген статикалық файлдарды өзі көрсетеді. Қосымша `dist`, Python немесе Sites build командасын бермеңіз; ескі custom build override болса, жобаның осы native конфигурациясына сәйкестендіріңіз. `npm run build:vercel` — тек жергілікті орналастыру көздерін тексеру, Vercel панеліне қоюға міндетті build командасы емес.

**Жаңа Vercel жоба жасамаңыз және негізгі доменді ауыстырмаңыз.** PR тармағы үшін автоматты deployment `vercel.json` арқылы өшірілген; бұл қосымша Preview жасамау үшін. Preview-ге нақты Supabase-ті қосуға рұқсат беретін айналып өту қосылмаған.

### 3. Рұқсаттан кейін PR №1-ді біріктіріп, бар доменді тексеру

GitHub тексерулері жасыл болғанын тексеріңіз. Иесі Production-ға жариялауға **бөлек рұқсат бергеннен кейін ғана** PR №1 негізгі `main` тармағына біріктіріледі. Қолданыстағы Vercel Git байланысы жаңа Production құрастыруын бастайды. **Deployments → Ready** шыққан соң бұрынғы https://ustaz-bilimai.vercel.app/ ашылады. Бұл жұмыста merge немесе deploy орындалған жоқ.

Егер Git байланысы не негізгі тармақ басқа болса, алдымен панельде тексеріңіз; тексермей «Redeploy» басу ескі кодты қайта шығаруы мүмкін. Vercel-ге тікелей әкімшілік қолжетімділік бұл ортада жоқ, сондықтан сол панельдегі құрастыруды орындап растау иесінің міндетті әрекеті болып қалады.

## Қабылдау тексеруі

1. Бұрынғы мұғалім өз құпиясөзімен кіреді; өзінің оқушыларын және нәтижелерін көреді.
2. Бұрынғы оқушы мұғалім берген логинмен кіреді; барлық 19 тақырыпты, 2 B/10 C тапсырманы ашады.
3. Тапсырманы жібермей жауап/шешім көрсетілмейді. Дұрыс және қате жауап жібергенде тиісті түсіндірме шығады. Қате жауапта қатені талдау беріледі.
4. Бетті жаңарту, шығу/қайта кіру және басқа құрылғыдан кіру нәтижелерді сақтайды. Оқушы басқа оқушының нәтижесін көрмейді.
5. Мұғалімнің телефондағы нәтижелерін және CSV жүктеуін тексеріңіз. Редактор жауапты тек мұғалімге ашады; өзгеріс жаңа нұсқа, бұрынғы әрекеттер өз нұсқасын сақтайды.
6. Тіркеу/құпиясөз өзгерту/тапсырма өңдеу сынағын тек алдын ала келісілген тест аккаунтымен орындаңыз; нақты оқушылардың құпиясөзін тексеру үшін өзгертпеңіз.
7. ҚМЖ жаңа интерфейсте жоқ. `/scripts/`, `/supabase/`, `/ops/` құпия материалдары сайт арқылы берілмеуі керек.

Ақау шықса, Vercel-де алдыңғы тұрақты deployment-ке қайтыңыз. Жаңа Supabase кестелерін жоймаңыз және дерекқорды reset жасамаңыз: нәтижелер сақталуы керек. 006 миграцияның профиль рұқсаттары ескі интерфейстің кейбір өзгерту әрекеттеріне әсер етуі мүмкін; кодты кері қайтару дерекқор саясатын автоматты өзгертпейді.

## Нақты тексерілгені және шектеуі

Жергілікті тексерулерде алты SQL миграциясы, бастапқы орнатудың транзакциясы, барлық 228 есептің дұрыс/қате жауаптары, RLS оқшаулауы, рөл қорғанысы, тапсырма нұсқалары және сеанс тоқтату сынақтан өтеді. Браузер сынағы 19 тақырыпты, барлық 228 карточканы, нәтиженің сақталуын, тіркеуді, редакторды, CSV және құпиясөз әрекеттерін тексереді. Python/SQL/HTML/CSS/Excel есептері бөлек тексеріледі.

Auth жергілікті браузер сынағында эмуляцияланған; SQL нақты жергілікті PostgreSQL (PGlite) арқылы орындалады. Бұл нақты Supabase Auth, Production-дағы RLS үйлесімділігі және Vercel бұлттық құрастыруы тексерілді деген сөз емес. Дерекқор өзгерісі, нақты аккаунтпен кіру, Vercel құрастыруы мен жариялауы осы жұмыста орындалмады. Сайттың ашық GitHub-тағы авторлық жауап файлдарына қарау мүмкіндігі бар; олар Vercel браузер жүктемесіне қосылмайды.

Әзірлеуші тексерулері: `npm run check`, `npm run seed:check`, `npm test`, `npm run build:vercel`, `npm run test:programs`, `npm run test:excel`, `npm run test:ui`, `npm run test:css`. Пайдаланушыға бұл командаларды орындау немесе бағдарлама орнату талап етілмейді.

Ресми анықтамалар: [Vercel Git deployment баптауы](https://vercel.com/docs/project-configuration/git-configuration), [Vercel builds](https://vercel.com/docs/project-configuration#builds), [Supabase sessions](https://supabase.com/docs/guides/auth/sessions), [Supabase әкімшілік аккаунт жаңарту](https://supabase.com/docs/reference/javascript/auth-admin-updateuserbyid).
